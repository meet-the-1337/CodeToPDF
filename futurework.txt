Prompt A — Build Debian package (.deb) and attach to release

Create a Debian package for the existing code-to-pdf Linux binary and attach it to GitHub Releases. Steps:
1) Create a packaging folder debpkg/DEBIAN and debpkg/usr/local/bin.
2) Copy the built Linux executable into debpkg/usr/local/bin/code-to-pdf and set executable permissions.
3) Create debpkg/DEBIAN/control with fields: Package (code-to-pdf), Version (v1.0.0), Section (utils), Priority (optional), Architecture (amd64), Maintainer (Your Name <you@example.com>), Description (short description).
4) Optionally add postinst script to create desktop file in /usr/share/applications and set permissions.
5) Build .deb using dpkg-deb --build debpkg code-to-pdf-v1.0.0.deb.
6) Verify install locally with sudo apt install ./code-to-pdf-v1.0.0.deb and uninstall via sudo apt remove code-to-pdf.
7) In GitHub Actions build workflow, after generating code-to-pdf-linux, add steps to create the .deb and upload it as release asset named code-to-pdf_1.0.0_amd64.deb.
Return: packaging scripts, control file contents, and updated build.yml snippet that produces and uploads the .deb.

Prompt B — Build AppImage (portable Linux single file)

Create an AppImage for the Linux binary so users can run on many distros without installing. Steps:
1) Create an AppDir structure (AppDir/usr/bin) and copy code-to-pdf binary into usr/bin.
2) Add AppRun wrapper that execs usr/bin/code-to-pdf.
3) Add desktop file and icon under AppDir/.
4) Use appimagetool to produce CodeToPDF-x86_64.AppImage.
5) Add AppImage creation to GitHub Actions and attach artifact named code-to-pdf.AppImage.
Return: AppDir layout, AppRun script, and workflow snippet to build and upload AppImage.

Prompt F — Add user-facing install instructions to README

Add short install instructions under Releases section to explain how to install each artifact:
- Linux .deb: sudo apt install ./code-to-pdf_1.0.0_amd64.deb
- AppImage: chmod +x code-to-pdf.AppImage && ./code-to-pdf.AppImage
- RPM: sudo dnf install ./code-to-pdf-1.0.0.x86_64.rpm
- Windows EXE: run setup .exe and follow installer
- macOS DMG: open and drag app to /Applications
Also add verification checksums (sha256) next to each asset.
Return: README snippet to paste into Releases notes.

Notes & guidance (short)

.deb requires user confirmation (sudo) — normal and expected. You cannot bypass that.
AppImage is frictionless for most Linux users — good fallback if you want “no install” option.
Uploading many installers is fine; users will pick the one for their OS.
Add checksums to release notes so users verify downloads.
In CI, ensure you sign or set appropriate permissions for macOS and Windows artifacts if you plan to distribute widely.
